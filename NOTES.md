# mwnote — журнал работы

Файл ведётся для сохранения промежуточных результатов между сессиями.
Секреты, пароли и содержимое рабочих БД сюда не записываются.

## Исходное задание (кратко)

- XMPP-бот на Python 3 + slixmpp 1.10 (ориентир Python 3.13).
- Конфиг: JID/пароль бота + массив JID администраторов.
- Личные сообщения: команды только от администраторов, остальным —
  «Не авторизован».
- Диалоговый режим: `add`/`del` для администраторов, `join`/`leave` для
  конференций, `wiki` для настройки MediaWiki, `switch` для выбора страницы,
  `+ текст`, `list`, `- номер`.
- Одна MediaWiki на всех; текущая страница — отдельно для пользователя и
  для конференции.
- В конференции: реакция только на обращение по нику через `:` или `,`;
  только модератор/админ/владелец; только команды заметок и `switch`.
- Хранение рабочих данных — sqlite3.
- После изменений кода — локальный git-коммит от `opencode (big-pickle)`.
- Пояснения пользователю — на русском.
- Тестовые зависимости — в скрытом каталоге, исключённом из git.

## Решения, согласованные с пользователем

1. Формат конфига — **INI** (`mwnote.conf`), как в соседних проектах.
2. После перезапуска бот **автоматически возвращается** в конференции,
   сохранённые в sqlite (`[muc] autojoin = true`).
3. Пароль MediaWiki хранится в sqlite **открытым текстом**, файл БД
   получает права `0600`; в git не попадает.
4. Пункты заметок на вики — строки верхнего уровня `# текст`; остальной
   текст страницы сохраняется.

## Архитектурные решения

- `core.py` не зависит от XMPP: диалоги и команды тестируются напрямую.
- `bot.py` отвечает за XMPP, проверку прав, MUC и доставку ответов.
- `storage.py` — sqlite: настройки wiki, текущие страницы по scope
  (`user:<bare>` / `room:<bare>`), список комнат для autojoin.
- `mediawiki.py` — stdlib `urllib` + cookie jar, login/CSRF/read/edit.
- `notes.py` — разбор и изменение только строк `# ...`, сохранение
  остального текста страницы.
- Транзиентные состояния диалогов — в памяти (пароль wiki не пишется в БД
  на этапе ввода).

## Вопросы и ответы

| Вопрос | Ответ |
|---|---|
| Формат конфига? | INI, как в соседних проектах |
| Autojoin после рестарта? | Да, по умолчанию |
| Пароль MediaWiki? | Открытым текстом, БД chmod 600 |
| Формат заметок на вики? | `# пункт`, остальной текст сохранять |

## Журнал

### Сессия 1

- Составлен план, уточнены 4 решения (см. выше).
- Code Brain `agent_plan` вернул внутреннюю ошибку MCP
  (`Cannot read properties of undefined (reading 'filter')`); продолжаем без
  него, результат зафиксируем в `memory_store` в конце.

### Сессия 2

- Написаны `config.py`, `storage.py`, `mediawiki.py`, `notes.py`, `texts.py`,
  `core.py`, `bot.py`, `mwnote.py`, `selftest.py`.
- `config.py`: INI, дефолты, `set_admins` с атомарной перезаписью и
  сохранением комментариев, `chmod 0600`.
- `storage.py`: sqlite-схема `settings`/`pages`/`rooms`, `chmod 0600`.
- `mediawiki.py`: discovery `api.php`, login/CSRF, чтение/правка, защита от
  конфликтов через `basetimestamp`, повтор при `badtoken`.
- `notes.py`: строки `# ...` верхнего уровня, сохранение остального текста,
  общий `asyncio.Lock`, повтор при `editconflict`.
- `core.py`: диалоги, команды, scope `user:`/`room:`, ограничения MUC.
- `bot.py`: XMPP-слой, проверка роли/affiliation, обращение по нику,
  autojoin, ответы частями до 3000 символов.
- `mwnote.py`: CLI, логирование, сигналы, graceful shutdown.
- Исправлено по ходу тестов:
  - autojoin теперь проверяет результат входа;
  - MUC-состояние одного участника не сбрасывается сообщением другого;
  - `0` в диалоге URL MediaWiki даёт `Настройка MediaWiki отменена.`;
  - `match_addressed` вынесена в тестируемую функцию.
- `selftest.py`: фейковый MediaWiki HTTP-сервер; проверки конфига, sqlite,
  клиента, заметок, диалогов, MUC-прав и разбиения ответов. Все проходят.
- Написаны `README.md` и `SPEC.md`.
- Следующий шаг: git-коммиты от `opencode (big-pickle)
  <opencode@localhost>`, затем `memory_store`.
