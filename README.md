# mwnote

XMPP-бот на Python 3, который служит интерфейсом к страницам-заметкам
MediaWiki. Работает в личных сообщениях (только администраторы из конфига)
и в многопользовательских конференциях (только модераторы и выше, только
команды заметок и `switch`).

Подробное описание поведения и форматов — в [SPEC.md](SPEC.md).

## Требования

- Python 3.11+ (проверяется совместимость с Python 3.13);
- `slixmpp==1.10.0`;
- доступ к XMPP-серверу и к MediaWiki с API (`api.php`).

HTTP-запросы к MediaWiki выполняются через стандартную библиотеку
(`urllib`), отдельный HTTP-клиент не нужен.

## Установка

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp mwnote.conf.example mwnote.conf
chmod 600 mwnote.conf
```

Отредактируйте `mwnote.conf`: JID и пароль бота, список администраторов,
параметры конференций. Пароль MediaWiki можно задать там же или позже
командой `wiki` в личном чате с ботом.

Запуск:

```bash
python3 mwnote.py -c mwnote.conf
python3 mwnote.py -c mwnote.conf -d   # подробный лог
```

Без `-c` используется `mwnote.conf` рядом с `mwnote.py`. Если в `[jabber]`
заданы `host` и `port`, бот подключается к ним напрямую, иначе используется
SRV-запись домена.

## Запуск через systemd

В репозитории есть образец `mwnote.service.example` для размещения:

- проект — `/opt/mwnote`;
- конфиг — `/etc/mwnote/mwnote.conf`;
- SQLite — `/var/lib/mwnote/mwnote.sqlite3`;
- пользователь сервиса — `mwnote`.

Создайте пользователя и подготовьте каталог проекта:

```bash
sudo useradd --system --home-dir /opt/mwnote --shell /usr/sbin/nologin mwnote
sudo install -d -o mwnote -g mwnote /opt/mwnote
# разместите файлы проекта в /opt/mwnote
sudo chown -R mwnote:mwnote /opt/mwnote
sudo -u mwnote python3 -m venv /opt/mwnote/.venv
sudo -u mwnote /opt/mwnote/.venv/bin/pip install -r /opt/mwnote/requirements.txt
```

Разместите конфиг и задайте абсолютный путь к БД:

```bash
sudo install -d -m 0750 -o root -g mwnote /etc/mwnote
sudo install -m 0600 -o mwnote -g mwnote mwnote.conf /etc/mwnote/mwnote.conf
```

Файл конфига должен быть доступен сервису на запись: команды `add` и `del`
перезаписывают его.

В `/etc/mwnote/mwnote.conf`:

```ini
[storage]
db_path = /var/lib/mwnote/mwnote.sqlite3
```

Относительный `mwnote.sqlite3` попал бы в `/etc/mwnote`, куда сервису
писать нельзя. Каталог `/var/lib/mwnote` создаётся автоматически
директивой `StateDirectory=mwnote`.

Установите и запустите unit:

```bash
sudo cp mwnote.service.example /etc/systemd/system/mwnote.service
sudo systemctl daemon-reload
sudo systemctl enable --now mwnote
```

Логи:

```bash
journalctl -u mwnote -f
```

После обновления кода:

```bash
sudo systemctl restart mwnote
```

Пути, пользователя и имя unit-файла можно изменить под своё размещение.

## Первичная настройка

1. Напишите боту в личные сообщения с JID из `[admins] list`.
2. Отправьте `wiki`, укажите URL вики (например,
   `https://wiki.example.com`), логин и пароль.
   Для вики с двухфакторной аутентификацией используйте bot-password.
3. Отправьте `switch Заметки` — страница будет создана, если её нет.
4. Добавляйте пункты командой `+ текст`, смотрите `list`, удаляйте `- номер`.
5. Для конференции: `join room@conference.example.com [ник]`.
   Бот запомнит комнату и вернётся в неё после перезапуска
   (`[muc] autojoin = true`).

## Команды в личном чате

| Команда | Действие |
|---|---|
| `switch <страница>` | выбрать или создать страницу заметок |
| `+ <текст>` | добавить пункт (без текста — бот спросит) |
| `list` | показать пункты с номерами |
| `- <номер>` | удалить пункт (без номера — бот покажет список) |
| `status` | показать текущую страницу и адрес MediaWiki |
| `wiki` | настроить URL, логин и пароль MediaWiki |
| `add [JID]` | добавить администратора |
| `del [JID]` | удалить администратора (последнего удалить нельзя) |
| `join <комната> [ник]` | войти в конференцию |
| `leave [комната]` | выйти из конференции |
| `help` | справка |

Диалоговые шаги можно отменить словом `отмена` (или `0`, `cancel`).
Не-администраторам бот отвечает ровно `Не авторизован`.

## Работа в конференции

Бот реагирует только на обращение по своему нику через `:` или `,`:

```
бот: list
бот, + купить молоко
```

Доступны только `switch`, `+`, `list`, `-`, `status` и `help`. Остальные
команды игнорируются или получают ответ, что в конференции они недоступны.
Команда `help` показывает подробное описание каждой доступной команды.
Минимальная роль задаётся в `[muc] min_role` (`visitor`, `participant`,
`moderator`; по умолчанию `moderator`). Владельцы и администраторы
конференции допускаются всегда. Сообщения без обращения, своя история
и сообщения самого бота игнорируются; без стандартных прав бот не отвечает.

Если в `[muc] editor_hat_title` задан title шапки XEP-0317, участник
с этой шапкой получает весь набор команд конференции независимо от
`min_role`. Сравнение title точное; шапки назначаются администраторами
комнаты. Механизм действует в любой комнате, где присутствует бот.
XEP-0317 имеет статус Experimental и зависит от обновлений presence.

Текущая страница хранится отдельно для каждого пользователя и каждой
конференции, поэтому `switch` и заметки в комнате не меняют личный выбор.

## Формат заметок

На вики-странице заметкой считается строка верхнего уровня:

```wikitext
== Заголовок ==
# первый пункт
# второй пункт

Остальной текст страницы сохраняется.
```

Вложенные строки (`## ...`) заметками не считаются. При добавлении новый
пункт вставляется после последнего пункта, при удалении остальной текст
страницы не затрагивается. Нумерация в `list` и `-` идёт по порядку пунктов.

В примечании к правке MediaWiki указываются действие и ник автора команды.
В личном чате используется локальная часть JID, в конференции — ник участника.

## Данные и безопасность

- `mwnote.conf` содержит пароль XMPP-бота; файл исключён из git.
- SQLite (`*.sqlite3`) создаётся с правами `0600`; в нём хранятся настройки
  MediaWiki, включая пароль в открытом виде, текущие страницы и список
  конференций. Каталог с БД должен быть доступен только доверенным лицам.
- Команды `add`/`del` перезаписывают только строку `list` в `[admins]`,
  сохраняя остальные комментарии и настройки; файл получает права `0600`.

## Проверка

Офлайн-тесты не требуют XMPP-сервера и используют фейковый MediaWiki:

```bash
python3 -m compileall .
python3 selftest.py
```

Selftest проверяет конфиг, sqlite, клиент MediaWiki, разбор и изменение
заметок, примечания к правкам с ником автора, диалоги, `status`, подробную
справку MUC, вход в MUC без темы комнаты, доступ по шапкам XEP-0317,
MUC-ограничения и права, разбиение длинных ответов.

## Ограничения

- Одна MediaWiki и одна учётная запись на весь экземпляр бота.
- Нет автоматического переподключения к XMPP: после потери соединения
  процесс завершается (перезапуск — через systemd, пример —
  `mwnote.service.example`).
- Пароль MediaWiki хранится в SQLite без шифрования.
- Если автовход в комнату после рестарта не удался, запись о комнате
  сохраняется; используйте `leave` и `join` для повторного входа.
