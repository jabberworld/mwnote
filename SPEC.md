# mwnote — спецификация

## 1. Назначение

`mwnote` — XMPP-бот, который позволяет вести списки заметок на страницах
MediaWiki. Бот работает в двух режимах:

- личные сообщения — полный набор команд, только для администраторов;
- многопользовательские конференции (MUC) — только команды заметок и
  `switch`, только для модераторов и выше.

Один экземпляр бота использует одну MediaWiki и одну учётную запись
MediaWiki. Текущая страница хранится отдельно для каждого пользователя
и каждой конференции.

## 2. Технологии и ограничения

- Python 3.11+; код совместим с Python 3.13.
- `slixmpp==1.10.0` — единственная внешняя зависимость.
- MediaWiki API — через `urllib` из стандартной библиотеки.
- Рабочие данные — SQLite из стандартной библиотеки.
- XMPP-плагины: `xep_0030`, `xep_0045`, `xep_0085`, `xep_0184`, `xep_0199`.
- Сетевые вызовы MediaWiki выполняются в `asyncio.to_thread`, чтобы не
  блокировать XMPP event loop.

## 3. Конфигурация

Формат — INI, кодировка UTF-8. Путь задаётся `-c/--config`; по умолчанию
`mwnote.conf` рядом с `mwnote.py`.

### `[jabber]`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `jid` | — | JID бота; обязателен |
| `password` | — | пароль XMPP; обязателен |
| `resource` | `mwnote` | ресурс, если не указан в JID |
| `host` | пусто | XMPP-хост; вместе с `port` отключает SRV |
| `port` | пусто | порт XMPP |

### `[admins]`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `list` | пусто | JID администраторов через запятую или с новой строки |

Список изменяется командами `add`/`del`. При перезаписи сохраняются
комментарии и остальные секции файла; файл получает права `0600`.
Последнего администратора удалить нельзя.

### `[muc]`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `min_role` | `moderator` | `visitor`, `participant` или `moderator` |
| `default_nick` | локальная часть JID | ник при входе в комнату |
| `autojoin` | `true` | возвращаться в сохранённые комнаты после старта |
| `editor_hat_title` | пусто | title шапки XEP-0317, дающей права в MUC |

Независимо от `min_role`, affiliation `owner` и `admin` всегда допускаются.
Если задан `editor_hat_title`, участник с шапкой такого title также получает
доступ к командам заметок. Сравнение title точное, после `strip`; пустое
значение отключает механизм.

### `[wiki]`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `url` | пусто | начальный URL MediaWiki |
| `user` | пусто | начальный логин |
| `password` | пусто | начальный пароль |

Значения используются только при первом старте, пока в SQLite нет URL.
Дальше настройки хранятся в SQLite и меняются командой `wiki`.

### `[storage]`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `db_path` | `mwnote.sqlite3` | путь к SQLite; относительный — от каталога конфига |

### `[interface]`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `language` | `ru` | язык ответов (сейчас только `ru`) |
| `chat_markers` | `true` | XEP-0085 (состояние набора) и XEP-0184 (доставка) |

## 4. Хранилище

SQLite, права файла `0600`. Схема:

- `settings(key TEXT PRIMARY KEY, value TEXT NOT NULL)` — `wiki_url`,
  `wiki_user`, `wiki_password`;
- `pages(scope TEXT PRIMARY KEY, title TEXT NOT NULL, updated_at INTEGER)`;
- `rooms(room TEXT PRIMARY KEY, nick TEXT NOT NULL, joined_at INTEGER)`.

Scope текущей страницы:

- `user:<bare JID>` — личный чат;
- `room:<bare JID комнаты>` — конференция.

Пароль MediaWiki хранится открытым текстом. Это осознанное решение:
SQLite-файл защищается правами доступа, а не шифрованием.

## 5. Авторизация

### Личные сообщения

Команда выполняется, только если bare JID отправителя совпадает с одним
из `[admins] list` без учёта регистра. Всем остальным отправляется ровно
`Не авторизован`, без дополнительных пояснений.

### Конференции

Бот реагирует на сообщение, только если:

1. оно пришло в комнату, где бот присутствует;
2. отправитель — не сам бот;
3. в теле есть обращение к нику бота, затем `:` или `,`;
4. сообщение не является историей (нет `<delay/>`);
5. отправитель имеет affiliation `owner`/`admin`, роль не ниже
   `[muc] min_role` или шапку XEP-0317 с title `editor_hat_title`.

Без стандартных прав и без подходящей шапки бот не отвечает. Сообщения
без обращения игнорируются. Команда из тела сообщения — всё после
`:` или `,`.

Шапки читаются из presence (`urn:xmpp:hats:0`) и кэшируются в памяти по
паре `(room, nick)`. Запись удаляется при `unavailable`/`error`, выходе
из комнаты и при новом `session_start`. Бот доверяет шапкам из любой
комнаты, где присутствует; шапки назначаются администраторами комнаты.
XEP-0317 имеет статус Experimental: если комната не поддерживает шапки
или не рассылает обновлённый presence, доступ может не измениться до
следующего presence или переподключения.

## 6. Команды

### 6.1. Общие команды заметок

| Команда | Поведение |
|---|---|
| `switch <страница>` | проверить/создать страницу, сохранить как текущую |
| `switch` | запросить адрес страницы |
| `+ <текст>` | добавить пункт в конец списка |
| `+` | запросить текст заметки |
| `list` | показать пункты с номерами |
| `- <номер>` | удалить пункт по номеру |
| `-` | показать список и запросить номер |
| `status` | показать текущую страницу и адрес MediaWiki |
| `help` / `?` | справка |

`status` показывает текущую страницу своего scope и URL MediaWiki из
SQLite, не выполняя сетевых запросов. Если страница не выбрана или
MediaWiki не настроена, выводится соответствующее уточнение.

Если текущая страница не выбрана, команды заметок возвращают
`Сначала выберите страницу: switch <название>.`

### 6.2. Команды только для личных сообщений

| Команда | Поведение |
|---|---|
| `wiki` | диалог настройки MediaWiki |
| `add [JID]` / `admin [JID]` | добавить администратора |
| `del [JID]` / `delete` / `remove` | удалить администратора |
| `join <комната> [ник]` | войти в комнату и сохранить её |
| `leave [комната]` | выйти из комнаты и удалить её из списка |
| `cancel` | отменить диалог |

В конференции эти команды недоступны; ответ:
`В конференции доступны только команды switch, +, list, -, status и help.`

### 6.3. Диалоги

Диалоговое состояние хранится в памяти, привязано к scope и JID
инициатора, живёт 600 секунд. Слова отмены: `0`, `отмена`, `cancel`,
`выход`, `exit`, `quit`. Для шага ввода URL MediaWiki слово `0` даёт
ответ `Настройка MediaWiki отменена.`, для остальных шагов — `Отменено.`

Шаги:

- `switch` → адрес страницы;
- `+` → текст заметки;
- `-` → номер пункта;
- `wiki` → URL → логин → пароль (пароль проверяется входом в MediaWiki
  до сохранения);
- `add` → JID;
- `del` → номер или JID из показанного списка;
- `join` → `комната [ник]`;
- `leave` → номер комнаты.

В конференции разрешены только диалоги `switch`, `+`, `-`; состояние
одного участника не отменяется сообщением другого участника.

## 7. Заметки на вики

Заметка — строка, соответствующая `^[ \t]*#(?!#)[ \t]*(.*)$`:
верхнеуровневый `#`, не `##`. Остальной вики-текст (заголовки, вложенные
списки, произвольный текст) сохраняется.

- Новая страница создаётся с комментарием
  `<!-- mwnote: страница заметок -->`.
- В примечании к правке указываются действие и ник автора команды:
  `mwnote: создана страница заметок (ник)`,
  `mwnote: добавление заметки (ник)`,
  `mwnote: удаление заметки (ник)`. В личных сообщениях ник — локальная
  часть JID, в конференции — ник участника (ресурс JID).
- Новый пункт вставляется сразу после последнего существующего пункта;
  если пунктов нет — в конец текста.
- Удаление убирает только строку пункта; нумерация оставшихся пунктов
  пересчитывается.
- Текст пункта нормализуется: пробельные последовательности сжимаются,
  пустой текст запрещён.
- Изменения сериализуются общим `asyncio.Lock`; при `editconflict`
  выполняется одна повторная попытка с чтением свежей версии.

## 8. MediaWiki API

1. Из URL строятся кандидаты `api.php`: `<path>/api.php`, `/w/api.php`,
   `/api.php`; для `index.php` — замена на `api.php`. Первый кандидат,
   ответивший на `action=query&meta=siteinfo`, становится API.
2. Вход: `action=query&meta=tokens&type=login`, затем `action=login`.
   При `NeedToken` выполняется повтор с выданным токеном.
3. CSRF: `action=query&meta=tokens`; при `badtoken` токен сбрасывается
   и запрос повторяется один раз.
4. Чтение: `action=query&prop=revisions&rvprop=content|timestamp&rvslots=main`.
5. Запись: `action=edit` с `assert=user`, `bot=1`, `watchlist=nochange`,
   `createonly` для создания и `basetimestamp` для защиты от конфликтов.
6. Ошибки API преобразуются в `MediaWikiError(code, info)`; сетевые ошибки —
   код `network`, неверный ответ — `badresponse`, отсутствие API — `noapi`.

## 9. XMPP-поведение

- После `session_start` бот отправляет presence со статусом-справкой.
- При `autojoin = true` бот входит в комнаты из `rooms`; фактический ник
  (если сервер изменил его) сохраняется.
- Длинные ответы разбиваются на части не более 3000 символов по строкам.
- В личном чате при `chat_markers` отправляется `composing`, затем
  `active` и запрос подтверждения доставки для первой части.
- Подписки на presence автоматически подтверждаются (`subscribed`).
- Комнаты входа/выхода обрабатываются через `xep_0045`; выход удаляет
  комнату из SQLite только после успешного выхода.
- Вход в MUC считается успешным после получения собственного presence;
  отсутствие темы комнаты не является ошибкой. При таймауте вход
  дополнительно подтверждается наличием роли в комнате.
- Шапки XEP-0317 читаются из `groupchat_presence` и кэшируются по
  `(room, nick)`; при изменении presence кэш обновляется.

## 10. Обработка ошибок

- Ошибки MediaWiki в личных сообщениях возвращаются как
  `Ошибка MediaWiki: ...` или `Не удалось переключиться на страницу ...`.
- Непредвиденные исключения логируются; пользователю отправляется
  `Внутренняя ошибка. Подробности в логе.`
- Ошибки конфигурации выводятся в stderr, код возврата `1`.
- При завершении по `SIGINT`/`SIGTERM` бот отключается и закрывает SQLite.

## 11. Тестирование

`selftest.py` не требует XMPP-сервера. Он поднимает локальный фейковый
MediaWiki HTTP-сервер и проверяет:

- загрузку конфига, сохранение администраторов, права файлов;
- SQLite: настройки, страницы, комнаты, `0600`;
- MediaWiki: discovery, login, чтение, создание, правку, ошибки;
- заметки: разбор, добавление, удаление, сохранение остального текста,
  примечания к правкам с ником автора;
- диалоги и команды `core.py`, включая MUC-ограничения, `status`
  и подробную справку конференции;
- вход в MUC без темы комнаты, ошибки presence и резервное подтверждение
  по роли;
- доступ по шапкам XEP-0317: точное совпадение title, удаление шапки,
  отключение пустым `editor_hat_title`;
- права MUC и разбиение длинных сообщений.

Запуск:

```bash
python3 -m compileall .
python3 selftest.py
```

## 12. Известные ограничения

- Одна MediaWiki и одна учётная запись на экземпляр.
- Нет автоматического переподключения к XMPP.
- Пароль MediaWiki не шифруется в SQLite.
- При неудачном autojoin запись комнаты остаётся; повторный вход — через
  `leave` и `join`.
- XEP-0317 Experimental: шапки зависят от поддержки комнаты и обновлений
  presence; title сравнивается точно и может зависеть от языка.
- Язык интерфейса только русский.
